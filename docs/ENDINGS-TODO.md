# Endings — status and TODO

## Done
* `EndingResolver.Resolve(GameState)` returns the `Ending` enum with the five rules from the brief
  (`GameState.DoorOpened` = fork 4 answered STRANGE). 30 EditMode tests cover state, rules and scene order.
* Five additive scenes `End_*` (built by `GreyboxBuilder.BuildEndings`, `Assets/TWIN/Editor/GreyboxEndings.cs`),
  each with a Timeline (`Assets/TWIN/Data/Endings/End_*.playable`): a **Beats** signal track whose markers
  call the `*Controller` methods. Move markers in the Timeline window to retime an ending.
* `GameManager.GoToNextScene()` after `07_LastMorning` loads the resolved ending additively;
  `useEndOfDemoFallback` (Inspector, TWIN_Persistent prefab) shows the END OF DEMO screen instead.
* "Press R to start a new run" prompt (`GameManager.ShowRestartPrompt`); R = `RestartDemo()` → reset + scene 1.
* `HapticsService` (TWIN_Persistent): click, slow pulse, heartbeat ramp, stop all. Logs on desktop, XR impulses on a headset.
* Play-tested on desktop: Good morning, Sam (full beat list works) and The note (beats, note text, prompt).

## TODO / known issues
1. **Animation tracks are unbound when generated by the builder.** The hand moving to the note and the
   figure sitting up (The note), and the mother turning (The funeral) do not play. The Timeline tracks
   and `.anim` clips exist and binding them by hand works (add an `Animator` to the object, drag it onto
   the track in the Timeline window, save the scene). The bug is in `TimelineBuild.Animate` in
   `GreyboxEndings.cs`: the `Animator` it adds and the `SetGenericBinding` do not survive the scene save.
   Workaround until fixed: bind them in the Timeline window after running the builder.
2. **The funeral, Wake up and System error were not play-tested yet** (the test harness used a state
   without a door). Test with debug state `strangeCount 1 + note pocketed` then open the door (funeral),
   `2 strange` + open the door (wake up), `3 strange` + open the door (system error).
3. **System error has no script yet** — the brief does not describe it. `SystemErrorController` is a
   placeholder (glitch, "SYSTEM ERROR", prompt).
4. **Wake up haptics**: the brief was cut off at "Haptics: all haptics"; implemented as "all haptics stop".
5. `WakeUpController.EnablePassthrough()` is an empty hook (comment explains what the Quest 3 passthrough needs).
6. Docs (ARCHITECTURE.md, HOW-TO-CHANGE.md, STORY.md) still describe the version without endings; update them.
